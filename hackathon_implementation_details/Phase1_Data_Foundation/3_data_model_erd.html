🎯 Basic Model: 6 Core Categories

This variant uses the 6 primary categories as defined in the problem statement: Infrastructure, Application, Security, Database, Storage, Network. Ideal for initial implementation and rapid prototyping.

Entity Relationship Diagram (Basic)

Key Features - Basic Model

1 Simplified Category Structure

Only 6 main categories with optional subcategory text field for flexibility

2 Direct Classification

Faster training and inference with fewer classes to predict

3 Easier Department Mapping

1:1 mapping between categories and IT departments

4 Lower Data Requirements

Need ~150 tickets per category (900 total) for balanced training

🔬 Granular Model: 24 Subcategories

This variant expands the 6 categories into 24 subcategories for precise routing and resolution. Better accuracy but requires more training data (50-100 tickets per subcategory = 1,200-2,400 total).

Core Tables Schema

tickets

Column Type Constraints Description
id SERIAL PRIMARY KEY Auto-incrementing ID
ticket_id VARCHAR(50) UNIQUE, NOT NULL External ticket ID (e.g., TKT-0001)
title VARCHAR(200) NOT NULL Short description
description TEXT NOT NULL Detailed problem description
category VARCHAR(50) Basic: 6 categories | Granular: 24 subcategories
priority VARCHAR(20) NOT NULL Low, Medium, High, Critical
status VARCHAR(20) DEFAULT 'new' new, in_progress, resolved, closed
assigned_to INTEGER FK → users(id) Assigned agent/department
created_at TIMESTAMP DEFAULT NOW() Ticket creation time
updated_at TIMESTAMP DEFAULT NOW() Last update time
resolved_at TIMESTAMP NULL Resolution timestamp

ticket_embeddings

Column Type Constraints Description
id SERIAL PRIMARY KEY Auto-incrementing ID
ticket_id INTEGER FK → tickets(id), UNIQUE Reference to ticket
embedding VECTOR(384) NOT NULL 384-dim vector from all-MiniLM-L6-v2
model_version VARCHAR(100) NOT NULL Model used for embedding
generated_at TIMESTAMP DEFAULT NOW() Embedding generation time

Indexes for Performance

-- Tickets table indexes
CREATE INDEX idx_tickets_category ON tickets(category);
CREATE INDEX idx_tickets_priority ON tickets(priority);
CREATE INDEX idx_tickets_status ON tickets(status);
CREATE INDEX idx_tickets_created_at ON tickets(created_at DESC);
CREATE INDEX idx_tickets_status_category ON tickets(status, category);

-- Embeddings vector index (IVFFlat for cosine similarity)
CREATE INDEX ON ticket_embeddings 
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);

-- Resolutions table indexes
CREATE INDEX idx_resolutions_ticket_id ON resolutions(ticket_id);
CREATE INDEX idx_resolutions_created_at ON resolutions(created_at DESC);

-- Classification table indexes
CREATE INDEX idx_classifications_ticket_id ON classifications(ticket_id);
CREATE INDEX idx_classifications_confidence ON classifications(confidence DESC);
